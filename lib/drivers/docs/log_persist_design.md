# Log 持久化后端设计（logger_store）

> 状态：设计讨论稿（2026-09-09）。**A/B/C/D 已确认；E/F 挂起**——裁决 10 将 services 侧 per-backend 模块过滤立为前置能力，先完成 log 服务过滤增强再续本稿。定稿前为草稿，不引用决策编号体系。

## 定位

log 服务持久化后端：把通过过滤的日志消息以记录形式可靠写入命名 flash 分区（黑匣子语义——环形覆盖保新），支持主动拉取导出；实例模型 = 一实例一分区，V1 单实例验证语义、多实例能力随结构体就位。

## 讨论裁决记录（随讨论逐条固化）

1. **路由语义（Q2 裁决）**：持久化 = 隐式扇出后端，被动接住所有通过 per-backend 过滤的消息；"显式"只存在于配置层（每后端级别/过滤），绝不进入 `OM_LOG_*` 调用 API。业界主流为广播/扇出模型（Zephyr log backend / spdlog sinks / logd buffer），调用点路由参数不存在于成熟框架；"显式投递"仅存在于独立 logger/记录 API（语义分离），不属日志 API。
2. **实例模型**：一实例一分区（业界锚点 rlog/EasyFlash/pstore 类别隔离）；V1 单实例验证。
3. **读出触发**：主动拉取为主（V1）；异常复位自动出 = 依赖复位源/meta 能力，随转存缺口立项演进。
4. **满区策略**：环形覆盖保新（黑匣子要最新现场；丢旧保新，扇区循环轮转 → 天然均匀磨损）。
5. **panic 落盘**：不直写（PAL 契约：flash 写必须让出 CPU，panic 域不可满足）。**框架缺口**（另立项）：panic 现场 RAM 暂存（NO_INIT 段 + magic/CRC）+ 复位后转存——V1 后端预留"转存入口"接缝。缺口立项理由 = 耦合方向（转存依赖后端的写入口与记录格式）+ 专属依赖栈（链接器双工具链/复位源/fatal 侧）与 log 服务零交集。
6. **写执行模型**：专用低优先级写线程（单写者，天然避开 PAL"回调上下文不得再提交请求"自锁禁令）；push 恒快仅行组装；水印/超时批量擦写；扇区预擦错峰；BUSY 有限重试（3 次）后丢弃计数。
7. **并发归属（三层）**：设备级 = PAL 执行域/队列收敛（深度 2，第三个并发请求 BUSY——上层不加锁）；分区级 = 分区表几何契约（不重叠、擦写物理隔离）；实例内 = 单写者线程全序。
8. **磨损均衡**：日志环顺序轮转 = 布局层均衡，V1 内建，无需 FTL 级动态映射（NOR 顺序环不适用；EEPROM/FRAM/MRAM 免擦不适用）。寿命预算 ≈ 10⁴ 擦写 × 扇区数 × 平均记录占用。
9. **缓存裁决（不加数据缓存层）**：真正的耗时 = erase（预擦轮转已消）+ program（µs 级，逐条可接受）+ read（顺序一次性，无重复读工作集 → 读缓存命中率≈0）。写累计 = 队列批写（已定）；读缓存/页缓存属于存在随机访问的层（文件系统/DB/FTL）——环形日志无此模式，业界环形库（rlog 类）均无读缓存。**V1 不加 RAM 数据缓存**：掉电丢失窗口可预期性（= 写队列深度）优先于无收益的缓存。演进触发：出现重复读/随机查询路径（meta 索引、启动回放全量读、查询命令）时在对应访问路径加页级缓存。
10. **前置能力排序（挂起 persist E/F）**：services 侧 **per-backend 模块过滤**（filter set：后端在级别之上按模块收日志；实现点 = log 服务消费编排——格式化前消息仍带结构化 module/level；Zephyr filter set 同构）先于 persist 设计定稿。persist 写侧模块过滤 = 继承该通用能力（自身不解析文本、config 无模块项）；读侧按模块筛选的结构化记录头诉求随该能力一并再议。记录头 V1 预留 version 字段作演进接缝（meta/结构化升级向后兼容）。

## A. 架构与组件

**归属**：实现住 `lib/drivers/src/storage/`（依赖 partition → drivers 层；服务接口经开放头 `services/log/log.h` 反向接入——串口后端先例；services/platform 均不合规：services 不得依赖 drivers、platform 不碰 services 开放面）。公共头 `lib/drivers/include/drivers/storage/log_persist.h`。

**分区接入（分区层 v2 形态，2026-09-15 适配）**：实例在 init 期以 `om_partition_open(reg, name, &h)` 取句柄并常驻私有态，此后数据通路一律走该句柄（`om_partition_read` / `om_partition_write` / `om_partition_erase_range`）——分区模块零状态（无全局查找、无 init 顺序依赖、API 天然可重入），故实例自身持有全部运行态；代价是**注册表对象须比实例活得久**（句柄按指针引用注册表）。本稿其余部分不受 v2 影响。

```
日志线程(广播)                 写线程(LOW, 可裁剪)
   │ push(段, 恒快)                  │
   ▼                                 ▼
行组装缓冲(拼\n成行)──完整行──► 待写环形(SPSC)──► 记录打包(头+CRC)
                                                  │
                                     扇区预擦轮转 ◄─┘
                                                  ▼
                                   om_partition_write(句柄, 同步, 线程态)
```

组件：① 后端实例（OmLogBackend 内嵌 + container_of 私有态：游标/计数/统计）；② 行组装+截断；③ 写队列（SPSC 定长）；④ 写线程（水印/超时；可裁剪开关退化同步批写）；⑤ 扇区环管理；⑥ 恢复扫描；⑦ 读迭代器（C 节）；⑧ 转存入口接缝（E 节）。

## B. 环形布局与写入

**布局**：分区 = N 扇区纯数据环，无独立元数据扇区。记录格式：`{magic16, len16, seq32, data…, crc16}`；记录不跨扇区（剩余不足即视为扇区满）；环形覆盖保新 = 扇区满时预擦最旧扇区续写。

**游标管理**：RAM 态 `curSector/curOff/nextSeq`；复位恢复 = 线性扫描（magic + crc 断链 + 0xFF 判空，坏点只有当前扇区尾部一处）；首启全区擦除；预擦轮转 `(cur+N-1)%N` 空闲时执行——擦（数十 ms）写（µs）错峰。

**写入路径**：push(段) 恒快 → 完整行入写队列（满丢新计数，不阻塞广播）→ 写线程批量 → partition 同步写 → BUSY 重试 3 次后丢计数；flush 钩子 = 写线程排空同步点。

### B 演进计划（触发条件驱动，未到不加）

| 触发条件 | 演进项 | 引入的复杂度（记账） |
|---|---|---|
| 转存立项落地（掉电/复位中断的确定性恢复需求） | 独立元数据扇区：最后提交游标/扇区状态（双备份+CRC） | meta 高频写 = 热点扇区 → meta 须自轮转/双缓冲；恢复从扫描推断变索引直读 |
| 单分区 ≥ ~32 扇区 / 启动扫描耗时显现 | meta 索引 log2 跳查（替代线性扫描） | 同上 + 索引一致性 |
| 需要任意位置随机读历史 | 分区内寻址读（meta 或游标表） | 同上 |
| 掉电保持需求（无电场景也要留现场） | 器件变体：Backup SRAM（VBAT 域）暂存——抽象留在器件层，不进通用契约 | 板级差异 |
| RAM 暂存转存缺口（另立项） | 转存入口实装 + NO_INIT 段（双工具链）+ 复位源判定 + magic/CRC | 链接器/启动/fatal 三块横切 |
| 黑匣子"看现场"（只要最近 N 条） | 倒序迭代（从 curSector 回读） | 低——迭代方向反向 + 计数 |
| 大分区导出的长缓冲压力 | 流式分页（导出方按页取，不持长缓冲） | 低——迭代器分页参数 |
| 出现重复读/随机查询路径（meta 索引、启动回放每 boot 全量读、查询命令） | 对应访问路径页级读缓存 | RAM 占用 + 一致性语义（见裁决 9） |

**V1 不做的**：meta 扇区、跨扇区记录、FTL 级均衡、掉电保真写入、panic 同步直写、RAM 数据缓存层（裁决 9）、倒序迭代（演进表）。

## C. 读接口与导出（主动拉取）

**语义定位**：格式知识（记录头/断链/扇区游标）收敛在后端一处——设备侧消费者用迭代 API 搬记录，host 离线解析走分区 raw 读 + 解析脚本（`tools/`）；两条路径共享同一份格式文档。

**迭代 API（草案，细节实现期钉死）**：

```c
typedef struct OmLogPersistIter {
    uint32_t sector;    /* 下一读扇区 */
    uint16_t off;       /* 扇区内偏移 */
    bool     active;    /* begin 已置、end 未清 */
    bool     truncated; /* 读期间环覆盖 → 截断 */
} OmLogPersistIter;

OmRet om_log_persist_read_begin(OmLogPersistStore *store, OmLogPersistIter *iter);
OmRet om_log_persist_read_next(OmLogPersistStore *store, OmLogPersistIter *iter,
                               char *buf, size_t cap, size_t *outLen); /* OM_OK + *outLen=0 = 读尽 */
void  om_log_persist_read_end(OmLogPersistStore *store, OmLogPersistIter *iter);
```

- **方向**：V1 全序（旧→新）；倒序/限量 = 演进表。
- **导出与写并发是常态**（复位后 app 继续打日志）：`begin` 置写挂起标志（写线程批间自停；push 照常入缓冲滞留，满丢新计数）；不选锁/快照绕行——读期间环形覆盖会让迭代读到被擦扇区，暂停写批简单且正确。导出低频，窗口可接受。
- **传输无关**：迭代器只出记录，字节搬运归调用方（RTT/串口/后门/JLink）。
