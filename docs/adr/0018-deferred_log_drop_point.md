# ADR-0018：日志早期缓冲（deferred）与丢弃点后验告警

- 状态：已实施（feature/log-deferred）
- 日期：2026-09-05
- 参考：ADR-0015 (log_service)

## 背景 (Context)

日志服务 v2（统一异步）落地后，调度器前的日志行为存在两个缺口（ADR-0015 (log_service)
预留给 v3 "deferred 缓冲挂接"）：

1. **后端注册前的启动日志静默丢失**：EARLIEST/BOARD 级 init 运行时后端尚未注册（默认 RTT
   后端、串口后端均经 `OM_INIT_DRIVER`）——过滤流水线"无后端接受"零开销返回，启动序列最前
   段（板级自举/故障线索最常出现处）不可见。
2. **未就绪窗口的调用侧阻塞**：DRIVER 级（后端已注册、队列未建）走同步兜底——慢速后端
   （如 UART 轮询 115200）当场阻塞调用方（init 线程上下文）。
3. **丢弃不可见**：队列满/参数超限丢弃仅进计数（`om_log_stats()` 可查），日志流内无从
   得知发生过丢弃——现场调试靠"翻统计"才发现。

## 考虑过的方案 (Options)

### 早期缓冲（deferred）形态

- **参数包环形**（OmLogMsg 数组，回放走 log_emit_args）：复用就绪路径；但时间戳在回放时
  才生成（发起时刻失真）；`%s` 指针在 init 函数返回后可能悬垂（调度器前栈变量——比异步
  契约更苛刻）。**否决**。
- **格式化字节环形 + 记录头**（[级别 1B][长度 2B][消息字节]）：实时流式格式化产出
  （入环即定型）→ 发起时间戳/发起顺序天然保留；无指针生命周期问题；回放 = 按条直接
  扇出（无需再格式化）。**采纳**——消息组成唯一事实源 = `log_emit_build` 核心
  （头部/格式化/尾部 \n），出环即一条完整消息。

### 缓冲满策略

- **环形覆写（保最新）**：最新日志优先；启动序头段被覆写——失焦。**否决**。
- **线性保最早 + 整条回滚**：写不下 = 整条回滚 + 计数（半条记录不入环——回放零帧同步）；
  启动序列窗口短、条数少，保最早 = 异常线索常在起始段。**采纳**。

### 回放时机与窗口关闭

- **独立 OM_INIT_LATE 回放**：与"异步就绪"解耦；但 LATE 前日志已就绪（队列早建）——
  回放太晚（业务日志先于启动段输出，时序倒挂）。**否决**。
- **log_async_init（OM_INIT_SERVICE）末尾关闭窗口 + 回放**：与"异步就绪"同一时刻；
  队列/线程创建失败也回放（此后未就绪走同步兜底，v1 语义兜底不减退）。**采纳**。

### 丢弃点后验告警

- **丢弃即计数，不告警**（现状）：不可见性缺口未解决。**否决**。
- **丢弃点内即时告警**：丢弃发生时直接打 WRN——丢弃与调用侧无失败路径契约冲突、
  高频丢弃刷屏。**否决**。
- **日志侧排空后按节流补发 WRN**：日志线程排水后 / 回放收尾时报告（增量 + 累计；
  节流间隔可配），直接 emit（不走队列——无递归）。**采纳**。

## 最终决策 (Decision)

- **早期缓冲（`OM_LOG_DEFERRED`，默认 1，仅异步模式生效）**：
  - 窗口 = 程序启动 → log_async_init 末尾（幂等 flush 关闭窗口）；未就绪且窗口开 →
    入环（临界区同构——与兜底路径同级保护）；窗口关 → 同步兜底（`OM_LOG_DEFERRED=0`
    时全程同步兜底）。
  - 环形 = 线性保持最早（`OM_LOG_DEFERRED_BUF_SIZE`，默认 1024B）；记录 =
    [级别 1B][小端长度 2B][消息字节（含尾部 \n）]；放不下 = **整条回滚 + 计数**。
  - 回放 = 按条 per-backend 过滤扇出（发起时间戳/发起顺序保留）；记录坏帧防御性截断。
- **丢弃点汇总**（`om_log_stats().dropped`）= 参数包超限 + 队列满 + 早期缓冲满；
  无后端接受/级别过滤 = 正常过滤语义，不计丢弃。
- **丢弃后验告警**：`log_drop_warn`（每丢弃点独立 `LogDropWarnState`）
  · 触发 = 累计数有新增量 && 距上次上报 ≥ `OM_LOG_DROP_WARN_INTERVAL_MS`（默认 1000，
  哨兵初值表示"从未上报"——首次放行）
  · 消息 = WRN 级（per-backend 正常过滤）`log drop: <site> dropped <N> (total <M>)`，
    N=增量、M=累计；site ∈ {queue-full, early-buffer}（参数超限走超限计数，不告警）
  · 执行 = 日志线程排水后 / 早期缓冲回放收尾（log_emit_args 直接 emit——不走队列无递归）
  · 告警模块 = 框架内部静态实例 "log"（不进模块注册表；按名调节 `om_log_module_set_level`
    NOT_FOUND 与用户模块互不干扰）
- **栈/内存账**：+1KB 早期缓冲（默认）+ 常量段状态；不在热路径（未就绪窗口仅 startup）。

## 影响 (Consequences)

- 正面：EARLIEST/BOARD 级日志不再静默丢失（后端注册后回放可见）；未就绪窗口调用侧不
  被慢速后端阻塞；队列满/缓冲满在日志流内自证（节流 WRN）+ 统计可查。
- 行为变化（默认开）：DRIVER 级日志（此前同步直出）改为延迟到 SERVICE init 回放
  （几毫秒后输出；时间戳仍为发起时刻）；+1KB RAM。
- 约束：早期窗口内 ISR 打日志守既有短消息纪律（临界区级保护）；`%s` 等在早期窗口内
  打印为现场应用（与异步契约同源——参数指针生命周期保证）；
  `OM_LOG_DEFERRED_BUF_SIZE` 下限 16B（编译期 `#error`）。
- 兼容：`OM_LOG_DEFERRED=0` 完全复现 v2 行为（同步兜底）；host 测试 filter 目标即以此
  守卫复现（deferred 目标另测缓冲语义/告警状态机）；公开 API 面零新增（`om_log_stats`
  语义扩展——累计值含新增丢弃点）。
- 演进（v3 后续）：shell over RTT（通道协调）可与告警联动（shell 侧查丢弃）；告警
  site/内容扩展为配置化留待按需。
