# 存储系统形态与芯片特性影响（锚点文档）

> **状态**：工作锚点（2026-09-06 建立）——存储系统全景知识与目标形态。设计任何存储上层（分区表/槽布局/日志持久化/配置持久化）前回读本文；新器件类型或新特性出现时追加，不重排既有条目。

## 1. 芯片特性谱系

| | NOR | NAND | EEPROM | FRAM | MRAM |
|---|---|---|---|---|---|
| 原理 | 浮栅 | 浮栅（堆叠） | 浮栅（薄氧） | 铁电 | 磁隧穿 |
| 读 | 随机 + XIP | 仅页缓冲（无 XIP） | 字节随机 | 字节随机 | 字节随机 |
| 写 | program：字/页，1→0 单向 | 页写，1→0 | 字节双向改写（内部透明处理擦写） | 字节双向、快 | 字节双向（控制器可呈现 NOR 语义） |
| 擦除 | 显式、扇区 | 显式、大块 | 无擦除动作 | 无 | 物理无；为兼容可保留块几何 |
| 坏块/ECC | 无 | 出厂 + 使用中坏块、必须 ECC | 无 | 无 | 无 |
| 寿命 | 10K~100K 次 | MLC 1K~10K 次 | 100K~1M 次 | 1e10~1e12 | 1e12+ |
| 写前擦除准备 | 必须先擦 | 必须先擦 | 不需要 | 不需要 | 若按 NOR 呈现则需 |

**三条分界**（决定软件义务归属）：
1. 擦除动作存在性与单位；
2. 写双向性与粒度；
3. 坏块/ECC 存在性。

其余维度（容量/速度/成本）只影响"要不要管理层"，不影响接口语义。

**受管封装（managed flash）不入裸片谱系**：SD/TF 卡、eMMC、U 盘 = NAND + 控制器（FTL：坏块/ECC/磨损/映射全在卡内固件）。主机看到的接口是**磁盘语义**——固定扇区（512B）、可覆盖写、无擦除动作、容量恒定。裸片三条分界的全部义务被封装吞掉——受管与否是主机义务归属的最终决定者。

## 2. 特性 → 软件义务 → 分层（九条推导）

核心思想：**芯片特性不直接决定 API 形状——它决定软件义务的归属层**。同一特性在不同规模场景把义务推到不同层（NOR 在 MCU 上磨损义务可留业务层；NAND 必须进管理层）。

| # | 芯片特性 | 强加的软件义务 / 允许的结构 | 成熟框架验证 | OMR 落点 |
|---|---|---|---|---|
| 1 | 破坏性写（擦→program 两段） | 显式擦除 API；写不自动擦，已擦为调用方义务 | 全部一致 | FlashOps 语义已立 |
| 2 | 写单向 1→0、有最小粒度 | 写对齐强制（writeUnit）；program 语义文档化（逐位 AND、0→1 后果不定） | 写块尺寸参数 / 写粒度常量 | 已立 |
| 3 | 擦除粒度大且可能非均一 | 整扇区擦 API；擦除对齐义务上收分区层 | 扇区表 / 区域表 | 几何双模已立 |
| 4 | 擦/写耗时 ms~s | 同步阻塞 + 可睡眠锁；异步为扩展口 | 可睡眠锁共识 | 已立（锁在设备层） |
| 5 | 写原子性差、掉电任意点 | 上层事务化：intent 先行、meta 双份轮转、staging 先行 | bootloader trailer / ota 状态小块 | 已立（上层义务，K 档案） |
| 6 | 读模型 XIP vs 页缓冲 | XIP → 原地执行类 boot；映射属链接期事实，接口层不承载 | flash API 无 mapped 基址 | 已立（几何不承载基址） |
| 7 | 寿命有限 | 磨损管理按场景分层：小块循环 → 存储服务层环形轮转；海量块 → 管理层/FTL | 磨损均衡上收到卷管理层 | 已划给存储/日志层（P 档案） |
| 8 | 坏块/ECC（NAND） | 新接口维度（坏块查询/标记、ECC），不混入 NOR 路径 | NAND 独立 API / 坏块表 + 卷层 | 扩展口 ER-2 |
| 9 | 字节双向可改写、无擦除（EEPROM/FRAM/电池 RAM） | 完全另一族：无擦除、无分区、无磨损焦虑 | eeprom 设备类 / nvmem 子系统 | 扩展口 ER-3 |
| 10 | 受管封装（NAND+FTL 控制器：SD/eMMC/U 盘） | 第三接口形态：扇区块设备（覆盖写、无擦除、无磨损义务）；驱动 = 总线协议栈（初始化序列/命令调度/错误恢复）+ 块视图 + FS 或 raw 流式 | 块设备栈 / disk 抽象层（不进裸片 flash 抽象） | 扩展口 ER-5 |
| — | 擦后值不总是 0xFF | erasedValue 查询 | 参数查询 | 已立 |

## 3. 目标形态：可擦存储族 + 随机器件族

对标"可擦存储（分层抽象）+ 随机器件"的业界形态，MCU 裁剪版：

```
OMR 存储系统（目标形态）

消费层（按需求形态选族）
  ├─ bootloader 槽/meta      → 可擦族（大块、XIP、事务化）
  ├─ OTA staging / 日志持久化 → 可擦族（流式 + 磨损轮转 = 存储服务）
  │                          → 或块设备族（SD/eMMC：FTL 内建，FS 或 raw）
  └─ 配置/标定/序列号         → 随机器件族（小、频繁改）或 meta 区

可擦存储族（维度：擦除几何 + 单向写）      随机器件族（维度：无擦除 + 双向写）
┌───────────────────────────────┐      ┌───────────────────────────────┐
│ 管理模块（按特性可选加入）        │      │ 字节存储接口                  │
│   分区表 / 槽布局                │      │   read / write / get_size     │
│   磨损环形轮转                   │      └───────────────────────────────┘
├───────────────────────────────┤      块设备族（维度：扇区 + 覆盖写）
│ 器件族                          │      ┌───────────────────────────────┐
│   NOR（v0 已落地）               │      │ disk 风格接口                  │
│   MRAM（免擦并入：erase 可缺省）  │      │   read / write + 扇区几何 +    │
│   NAND（独立面：ECC/坏块维度）    │      │   可选 ioctl                   │
└───────────────────────────────┘      │   器件：SD/eMMC/U 盘/虚拟盘     │
                                        └───────────────────────────────┘
```

## 4. 演进留口（ER-xx：记录在档，有触发才实现）

| 编号 | 内容 | 触发条件 | 参照 |
|---|---|---|---|
| ER-1 | 免擦器件并入可擦族：erase 回调允许缺省（注册校验放宽），免擦设备上 flash_erase 返回 NOT_SUPPORTED | MRAM/自动擦 NOR 需求出现 | 免擦能力位 + 软件擦平原语 |
| ER-2 | NAND 独立面：坏块查询/标记、ECC 语义（几何与 ops 扩维，或独立 API 族） | NAND 进入目标平台 | NAND 独立 API / 无 NAND trait 先例 |
| ER-3 | 随机器件族落地：read/write/get_size 无擦除接口（可选 cell 语义） | EEPROM/FRAM 消费场景出现 | eeprom 设备类 / nvmem 子系统 |
| ER-4 | 管理模块化：分区表/槽布局、磨损环形（存储/日志层） | **已部分承接**（2026-09-07）：步骤② 布局数值拍板（bootloader 64K + A/B 双槽 + meta 独立区——ADR-0021 (boot_multi_strategy_skeleton)/multi_strategy_boot_design.md Q-02/03）；分区表抽象（P-03）随步骤② 前置落地；磨损环形仍待存储/日志层（步骤④） | flash_map / 分区表先例 |
| ER-5 | 块设备族落地：disk 风格接口（扇区读写 + 几何 + 可选 ioctl），对接 SD/eMMC/U 盘/虚拟盘；上层 FS（FAT/littlefs）或 raw 流式 | SD/eMMC 接入需求出现（如日志/OTA 固件暂存放 SD） | disk 抽象层先例 |

## 5. 分层纪律（沉淀）

1. **统一到共同语义集为止**：可擦族共同语义 = "擦除几何 + 单向写"；随机器件共同语义 = "字节读写"。差异语义（免擦/坏块/双向写）**不进公共接口**——用能力位、缺省回调或独立族表达。
2. **义务归属原则**：物理破坏性写 → 擦除 API + 调用方已擦义务；有限寿命 → 磨损归属存储/日志层（P 档案）；掉电不原子 → 上层事务化；XIP/映射 → 链接期事实不进接口。
3. **分族而非加维度**：新器件先按三条分界（§1）归类，再决定是并入现有族（能力位/缺省回调）、还是独立族/独立面——参考结论：没有把 NOR 与 NAND 揉进单接口的成功先例，EEPROM/FRAM 一律单列。
4. **受管封装 = 第三族，不是可擦族的扩展**：managed flash（SD/eMMC/U 盘）的 FTL 义务全在器件内，主机以扇区块语义接入（ER-5），绝不把块接口揉进裸片 flash 抽象。

## 6. 演进策略与边界原则

### 6.1 保留 / 演进判据（不以沉没成本与单一消费者为依据）

- 器件访问层是否保留，只看**平台物理需求与语义需求是否成立**：物理需求 = 存在须原地执行（XIP）+ 掉电保持的启动介质（片内 NOR 在目标板成立）；语义需求 = 事务化/分区管理需要"显式擦 + 已擦契约"。实现投入不构成判据。
- **开发次序 ≠ 依赖方向**：boot 方向先落地器件层是排期（最低层、零依赖）；架构依赖图恒为上层 → 器件层，无反向。
- 免擦 + XIP + 足够大的替代介质若出现，是"擦除语义退出"事件而非重构事件——退出机构已内建（ER-1）。

### 6.2 新器件路由：按语义维度，不按器件名

新器件出现 → 三问：
1. 有块/擦除几何吗？
   - 有且保留块几何的免擦器件（MRAM 类/自动擦 NOR）→ ER-1 并入可擦族（erase 缺省 + NOT_SUPPORTED）；
   - 无且字节双向（EEPROM/FRAM）→ ER-3 随机器件族；
2. 有坏块/ECC 吗（NAND）→ ER-2 独立面；
3. 是受管封装吗（SD/eMMC/U 盘）→ ER-5 块设备族。

ER-1 是双向机构：既收编 MRAM，也是"显式擦除从必选变可选"的退出通道。

### 6.3 块设备不是物理类，是呈现层契约

- 块设备契约 = 固定扇区 + 可覆盖写 + 无需擦除知识；三种出身：原生块器件（HDD/SSD/NVMe）、受管封装原生呈现（SD/eMMC——内部可擦 NAND + FTL 固件）、裸可擦器件 + 软件 FTL。
- **伪装块要付费，费用 = FTL**：坏块 + 磨损均衡 + 逻辑映射 + 掉电一致性全落主机。薄壳（block 视图不担 FTL 义务）只适合 NOR 的廉价传统 FS 场景；NAND 要块视图需软件 FTL 全套（UBI 级）。
- 与三族的关系：物理语义轴（可擦/字节双向）与呈现轴（块）不同轴；块设备族本质 = 受管封装的原生呈现层，与可擦族/随机器件族在"上层可消费视图"层并列自洽（§3 图）。
- MCU 推论：裸 NOR 上需要传统文件系统口味才做块壳；自管流式/日志场景直连裸 flash（如 littlefs 式免 FTL 税），不需块视图。

### 6.4 上层屏蔽规律：不发明"存储统一层"

成熟框架的事实：存储接口按族分立，**屏蔽发生在更高的"消费形态"接口**——上层声明自己的窄需求（文件 / 键值 / 流式追加），族内实现适配之；跨族选择在板配置/构建期绑定，不做运行时动态路由。

对 OMR 的应用：持久化日志后端将来声明"流式追加后端"窄接口（append/读回/重来/断点），实现者可落在可擦族（环形 + 磨损）或块设备族（SD raw，仅写对齐）——日志层语义相同，中间不需要通用存储层。

### 6.5 NAND 器件访问层的成熟度边界（ER-2 依据）

裸 NAND **没有**像 NOR 那样收敛的器件访问层形态：统一面 + OOB/坏块回调（为文件系统服务）/ 命令级 API（ECC/OOB 全留上层）/ 无 NAND trait / managed NAND（eMMC/SD）根本不暴露访问层。客观规律：**裸 NAND 几乎总是伴随管理层出现，其成熟形态天然在管理层**。故 ER-2 的"独立面"指"可管理的第一层"（坏块/ECC/OOB 维度自足，或直接是含最小管理的层），而不是往 NOR 面加维度。

### 6.6 设计不倒挂原则

- 器件访问层的每个决策必须能由**器件物理语义 + 业界收敛**独立解释，不引用任何上层消费者（bootloader/OTA/日志都是消费者，不是第一性）。
- 注释理由中立化的执行实例：擦后值注释不写"双份轮转判据"而写器件物理事实；掉电语义注释不举 boot 机制例子。
- 存储系统是独立架构资产：代码归位 drivers 层；文档目录归属（当前就近挂在 boot_ota 目录）随存储系统独立性提升再议。
